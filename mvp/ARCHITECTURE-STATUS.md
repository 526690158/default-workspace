# 架构落地状态

以根目录《企业操作系统-技术架构文档.md》v1.2 为准。此文件只记录实现状态，不修改架构原则。

| 架构部分 | 当前实现 | 尚需完成 |
|---|---|---|
| L1 岗位与责任 | 公司空间、ACC 岗位、负责人/监督/验收/禁止事项、自治等级；本地哈希审计链 | 真实身份认证、角色授权、工具与数据范围强制执行；独立且不可整体改写的审计存储；配套管理制度 |
| L2 任务编排 | 创建任务、完成标准、状态流转、交接、草稿验收 | 更严谨的验收判定、任务暂停与重试；复杂任务才引入 DAG |
| L3 认知协同 | 服务端部分 API 的硬规则与人工对齐检查 | 所有 L0 工具调用统一通过硬规则；金额/数据权限等业务规则；按需软校验 |
| L0 执行 | 新任务可由指定员工调用本机 Ollama 生成草稿；旧付费供应链推演已停用 | 把真实任务接入有工具权限的 Harness；受控工具调用、验证改进、真实多 Agent 协作 |
| L4 交互 | 双模式对话入口：Workflow 固定阶段、Agent 多轮工具调用；对话可建公司/岗位/任务，人工验收和部分审批 API | Agent 运行时接入 DSH；校验/查审计工具；澄清、协商、监督接管、反馈聚合、交互策略；审批界面 |
| L-M 记忆 | 无 | episode / preference / rule 存储、执行前召回、执行后沉淀和清理 |
| 多租户与部署 | 可在页面创建独立目录的公司空间 | 注册登录、可信租户隔离、容器隔离、配额强制执行、部署脚本 |

当前端到端体验遵循文档的最小闭环：**公司空间 → 岗位权责 → 任务与完成标准 → 硬规则 → AI 草稿 → 人工验收 → 审计记录**。AI 起草只生成文本，尚无外部发送或发布能力。身份仍由请求自报，不能作为真实企业追责依据。
