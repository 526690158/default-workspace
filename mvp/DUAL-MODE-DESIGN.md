# 双模式对话入口

参考 [Yoroll 预览站](https://preview.yoroll.ai/)的并列入口，以及本机 `LGPlatform` 的阶段工作流、`yoroll-agent-dsh` 的持续对话和工具调用方式。企业操作系统保留自身的 L1 岗位、L2 任务、L3 硬规则、L4 交互、审计链语义；未直接依赖这两个创作产品的业务后端。

| 维度 | Workflow | Agent |
|---|---|---|
| 入口 | 用户描述目标 | 用户描述目标 |
| 决策 | 固定的公司→员工→任务→执行→验收阶段 | LLM 根据目标和上下文选择管理工具，可跨轮调用 |
| 用户交互 | 每阶段提问，关键写入前确认 | 只在缺信息或创建/修改边界时确认 |
| 执行 | 当前仅 AI 起草、人验收 | 同一任务执行器，管理动作由工具调用组织 |
| 状态 | 持久化会话阶段 | 持久化对话与工具调用上下文 |

页面的表单仍作为高级配置留存。主路径从对话开始，创建公司是对话调用的工具。两种模式都使用同一套公司、岗位、任务、审批与审计数据；当前 Agent 管理循环与任务草稿使用本机 Ollama 的 `qwen3:4b-instruct`（可通过 `OLLAMA_MODEL` 更换本地模型），不会调用付费 DeepSeek API。旧 DSH 推演入口已停用，**尚未接入 `yoroll-agent-dsh` 的 DSH Runtime**。因此不要把当前 Agent 模式称作已具备 DSH 的多代理执行或受控外部工具能力。
