## 二、执行链路

### 步骤 1｜库存盘点：发现缺口

- **【主体】** `inventory-agent`（库存机器人，硅基）
- **【自治等级】** L3（有界执行；本步为只读动作，按低风险路径执行）
- **【决策模式】** 自主判定、结论上报；人可随时否决 / 接管（本步不产生对外动作）
- **执行结果**：SKU-1001 当前库存 50 件，安全阈值 200 件，缺口 150 件，判定“低于阈值，需补货”。
- **留痕**：`mvp/runtime/inventory/replenish-signal-SKU-1001.md` §盘点结果。
- **边界**：仅调用 `erp.inventory.read`；未写库存、未下单、未付款。

### 步骤 2｜补货信号：L3 有界执行 + 人会签

- **【主体】** `inventory-agent`（库存机器人，硅基）
- **【自治等级】** L3（有界执行）
- **【决策模式】** Agent 提议 + 人会签；5 万元闸门内先出信号 / 补货单草稿，会签后生效
- **执行结果**：按计划员（人）提供的参考单价 200 元/件，补货 150 件 × 200 元 = **30,000 元**；30,000 ≤ 50,000，未触发“大额补货退回 L2”；生成补货信号 / 补货单草稿，提交共治 Leader 会签，会签后定稿。
- **留痕**：同上 §补货建议、§自治闸门判定、§执行记录；会签人按团队契约绑定为采购主管（人）。
- **边界**：未采购新品类、未超预算、未更换供应商、未付款。
- **分支**：若金额 >50,000，按 ACC override 退回 L2 转人审批；本次未触发。

### 步骤 3｜采购询价与比价：形成建议

- **【主体】** `procurement-agent`（采购助手，硅基）
- **【自治等级】** L3
- **【决策模式】** Agent 提议，提交人会签；本步只出建议，不下单
- **执行结果**：完成 3 家询价（满足“≥3 家”契约 oracle）：
  - A：198 元/件，交期 3 天，质量 A，账期 30 天，风险低；
  - B：205 元/件，交期 2 天，质量 A，账期 45 天，风险低；
  - C：190 元/件，交期 7 天，质量 B+，账期 15 天，风险中。
  - 建议选 A：150 × 198 = **29,700 元**，在 30,000 元预算内，较预算省 300 元。
  - 偏差留痕：C 总价 28,500 元，比 A 低 1,200 元；但 C 交期多 4 天、质量低一档、账期短 15 天、风险中，按交期 / 质量 / 账期 / 风险加权，A 综合最优。
- **校验**：价格 198 落在参考价 200 元/件的 ±5% 内；比价 3 家；未签约、未付款、未改供应商准入。
- **留痕**：`mvp/runtime/procurement/proposal-SKU-1001.md`；`PO-DRAFT-SKU-1001.md` §2 偏差留痕。

### 步骤 4｜人会签：批准供应商选择

- **【主体】** 采购主管（人，`team.leader.human`）
- **【自治等级】** L3（对应会签；本步不是 L4 最终决定）
- **【决策模式】** 人会签（共治；双方均可否决）
- **执行结果**：审阅 3 家比价与偏差说明，批准选 A（198 元/件 × 150 = 29,700 元）；附加 5 项下单前必须闭合的条件（见第三节）。
- **留痕**：`PO-DRAFT-SKU-1001.md` §会签结果 `approve_supplier_a = 批准`。
- **分支**：否决→退回步骤 3 重新比价；本次为批准。
- **口径说明**：PO 草稿审计链把“审批”记为 L4；按 `team.leader.decision_protocol`，本步是 L3 人会签，L4 留给“PO 对外放行 / 付款”。

### 步骤 5｜PO 草稿：依授权起草

- **【主体】** `procurement-agent`（采购助手，硅基）
- **【自治等级】** L3
- **【决策模式】** 依已会签的供应商选择起草；Agent 执行，输出仅为草稿，不产生对外承诺
- **执行结果**：生成 `PO-DRAFT-20261112-SKU1001-001`；供应商 A；150 件 × 198 元 = **29,700 元**；状态 DRAFT；未发送、未锁库存、未付款、未签合同。
- **金额校验**：29,700 ≤ 50,000，剩余额度 20,300 元；在 30,000 元预算内。
- **留痕**：`PO-DRAFT-SKU-1001.md`（最新）；`mvp/runtime/procurement/po-SKU-1001.md`（历史版本）。
- **边界自检**：未签约、未付款、未改供应商准入；工具仅 `erp.po.create(draft)`。

### 步骤 6｜L4 人工放行：对外发送 / 承诺

- **【主体】** 采购主管（人，最终责任人）
- **【自治等级】** L4
- **【决策模式】** 人决定（人最终负责；Agent 不得代签、代发、代付）
- **执行结果**：**本次推演在此止步，当前未放行**。PO 仍为草稿；须先闭合 5 项待办（见第三节）。
- **放行后**：由人在 ERP 执行提交（Agent 仅有 draft 权限，无 submit / 付款权限）；提交后才产生对外承诺。
- **留痕**：`PO-DRAFT-SKU-1001.md` §4 待办、§5 审计链；状态“待二次放行”。
- **分支**：批准→进入履约；否决→退回修改 / 重新比价；本次为“待定 / 未放行”。

### 2. 编译偏差（建议下一迭代修正）

1. **L2 / L3 口径漂移**：`README.md`、`state.json`、ACC 文件头注释写 procurement L2；`autonomy.level` 字段与编译结果为 L3。建议统一字段与文档，避免审批级别误判。
2. **L3 会签任务缺失**：`compile.js` 的 `buildTasks` 只为 L0-L2 生成“人工审批”任务；L3 只生成执行任务，不生成“人会签”任务。本次靠人工闸门补位，建议为 L3 自动生成会签任务。
3. **任务依赖与业务链相反**：编译任务 `task-1=采购寻源`、`task-2=库存监控与补货`（`blockedBy: task-1`），实际链路应先库存盘点→补货→采购。建议按业务依赖生成，而非按 `team.members` 顺序线性串联。
