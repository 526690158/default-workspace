# 五分钟测试：两条对话链路

启动 `npm start` 后打开 `http://127.0.0.1:8091`。首页直接进入对话，并列展示 **Agent** 和 **Workflow** 两种模式。两者都会在对话中建立公司、员工与任务；页面不要求先点“创建公司”。

## Workflow：适合第一次体验

选「Workflow」，输入“我想办一个周末读书会”。系统将按公司 → 员工 → 任务 → 执行 → 验收提问。可以依次回答：

1. 公司叫“小林读书会”，负责人“小林”，阅读演示数据边界后回复“确认”。
2. 岗位叫“活动文案助理”，职责“起草活动通知”，禁止事项“不得编造时间地点，不得自行发送消息”，核对后回复“确认”。
3. 任务是“为周末读书会写一条群通知”；已知信息是“周六下午 3 点，社区活动室，免费，带一本喜欢的书”；完成标准是“写明时间、地点、费用和需带物品”，核对后回复“确认”。
4. 回复“开始”生成草稿。读完后回复“通过”或“退回”。草稿不会自动发送。

## Agent：观察自主工具调用

切换到「Agent」，输入：“帮我建立一个读书会团队，负责人小林，招一位只负责起草通知的活动文案助理，不允许自行发送；之后帮我安排周末邀请通知。”Agent 会自己选择工具，按缺失信息追问，并在创建公司、岗位、任务前展示边界，请你在对话中回复“确认”。每次调用的工具会显示在回复下方。

Agent 模式和 Workflow 的 AI 起草使用本机 Ollama。确认 `ollama serve` 正在运行，且 `ollama list` 中有 `qwen3:4b-instruct`。无需 API key；首次下载模型文件需要网络，之后推理在本机进行。若机器上只有 `qwen2.5:1.5b`，可用 `OLLAMA_MODEL=qwen2.5:1.5b npm start` 临时运行，但多步工具调用质量可能较弱。

旧「编译 / 运行」页的付费模型推演已停用；契约编译仍可用。
